# Аудит интерфейса и готовности 4rrum к закрытой альфе

Дата: 30 сентября 2026. Исходная версия: `b42854ddfd98fefc63fe7011da3f37c39c408506`.

## Вывод

Главная имеет узнаваемую визуальную систему, но переходы на служебные страницы разрушали её: белые поверхности, слабый контраст, другие логотипы. Для альфы важнее исправить эти разрывы и реальные сценарии участия, чем добавлять новые декоративные блоки. Компактная форумная структура, нейтральный графит и тематические иллюстрации сохранены.

Это аудит скриншотов, публичного интерфейса, исходного кода и автоматических проверок. Он не заменяет нагрузочное тестирование, проверку восстановления production-БД и полноценный независимый тест безопасности.

## Область проверки

- Два пользовательских скриншота: первый экран и нижняя часть главной.
- Живые главная, каталог сообществ, поиск, тема и каталог услуг: визуальная и семантическая проверка.
- Код регистрации, входа, восстановления доступа, редактора публикаций, ответов, заявок, модерации, API, метаданных, резервного копирования и выпуска.
- Браузерные сценарии на контролируемом API: главная, фильтры, меню, реакции/закладки/жалобы, страницы авторизации, поиск, поддержка, 404, гостевой ответ, заявка куратору и отправка ответа.
- Проверка ширин 320–1920 px для главной; 320, 390, 760, 1280 px для проверяемых служебных экранов.
- Runtime axe и проверки исходников. Автоматические проверки не гарантируют доступность каждого возможного состояния сайта.

## Находки и исправления

| Приоритет | Наблюдение | Внесённое изменение |
|---|---|---|

| Средний | При сбое SSR ленты клиент пропускает первый запрос, принимая сбой за пустой форум | Гидратация пропускает повторный запрос только при реально полученном feed |
| Средний | Услуги/проекты и цифровые сервисы выглядят как другой продукт | Графитовые поверхности; отдельные пустое, отфильтрованное и ошибочное состояния; повтор загрузки |
| Средний | Логотип внутренних страниц и авторизации отличается от главной | Тот же SVG-логотип с заданными размерами |
| Средний | На главной создание темы плохо обнаруживается; на телефоне мелкие подписи и короткие зоны нажатия | Текст действия на широком экране; более удобные мобильные кнопки/вкладки/описания; ясные подписи статистики |
| Средний | Названия кнопок для экранного диктора не содержат видимый текст | Доступные имена вкладок включают видимые названия |
| Средний | У новичка нет ясного маршрута обратной связи | Краткий блок альфы после ленты и инструкция в поддержке с переходом в действующее сообщество |
| Средний | В поддержке и правилах вложенный main; 404 без заголовка страницы; ошибка обещает сохранность данных без доказательства | Один главный landmark; h1 для 404/ошибки; точный текст ошибки |
| Средний | Мобильная навигация не обозначает текущую страницу | aria-current и видимое активное состояние |
| Средний | Форма заявки и восстановление доступа не имеют общего HTTP noindex | Добавлены noindex-заголовки и robots-ограничения для соответствующих маршрутов |
| Низкий | test:pure падает на TypeScript parameter properties в четырёх существующих тестовых файлах | Используется уже установленный tsx, как в основном запуске API-тестов |

## Что уже есть в коде

- Пароли хешируются Argon2id; cookie сессии HttpOnly, SameSite=Lax и Secure в production; токены сессий хранятся хешами.
- DTO проверяются с whitelist/forbidNonWhitelisted; есть ограничения запросов, проверки Origin, API Helmet и web security headers.
- Есть инструменты модерации, журнал действий, сохранение черновиков, управление сессиями, почтовое подтверждение и восстановление пароля.
- CI проверяет сборки, типы, API-тесты, интерфейс и визуальные регрессии; после выпуска проверяется версия production.
- Скрипт резервного копирования создаёт дамп БД, архив загрузок и контрольные суммы. Его локальная проверка использует заглушки, а не production PostgreSQL.
- Есть сбор LCP/INP/CLS в структурированные серверные логи. Наличие работающего production-дашборда и алертов этим аудитом не подтверждено.

## Проверки выпуска

- Основной набор API: 81 тест прошёл.
- Сборка production Web и TypeScript.
- Static, UX, accessibility source и site-audit guardrails.
- Регрессия главной: сценарии, геометрия, адаптивность, runtime axe, визуальные снимки.
- Расширение браузерной проверки на поиск, авторизацию, поддержку, 404 и заявки.
- Новые проверки безопасного возврата и отмены запросов включены в CI.
- Локальный тест backup-скрипта прошёл; восстановление реальной БД не выполнялось.

## Условия допуска и оставшиеся работы

| Перед каким этапом | Проверка | Статус/граница этого аудита |
|---|---|---|
| Перед приглашением новой группы | Два реальных тестовых аккаунта: регистрация → доставка письма → подтверждение → тема → ответ → уведомление → жалоба → модерация | Код и контролируемые сценарии проверяются; реальные SMTP/уведомления и действия владельца в production не проверялись |
| Перед приглашением новой группы | Backup БД и файлов на внешнем носителе; восстановление в отдельном окружении; время и ответственный | Скрипт есть; внешний backup и production restore-drill не подтверждены |
| Перед ростом аудитории | Наблюдение uptime/ошибок, оповещение ответственного, измеренные LCP/INP/CLS | Endpoint и структурированные логи есть; алерты, дашборд и полевые бюджеты не подтверждены |
| Перед несколькими API-процессами | Общие rate-limit counters вместо process memory | Требуется инфраструктурная работа; текущие лимиты локальны процессу |
| Перед публичным запуском | Нагрузка, зависимости, независимая проверка доступа по ролям и безопасности | Не объявляются завершёнными по результатам frontend-аудита |
| Постепенная стабилизация | Замена накопленного globals.css единой системой токенов и компонентных стилей | Добавлен ограниченный alpha-ui.css; массовый переписанный каскад без регрессий не включён |
| Решение владельца | Что делать с тестовыми темами «111…» и «тест тест» | Реальные публикации сохранены; удаление/скрытие не выполнялось |
| Решение владельца | Ограничивать ли альфу приглашениями | Регистрация открыта; код регистрации не проверяет приглашение. Название «закрытая альфа» само по себе не ограничивает создание аккаунтов |

Закрытую альфу следует вести как ограниченный тест основной форумной цепочки. Техническую готовность к массовому публичному запуску нельзя вывести только из исправленного внешнего вида и зелёного CI.
