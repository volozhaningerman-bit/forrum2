# FORRUM V26 — главная по утверждённым референсам

База: `volozhaningerman-bit/forrum2`, `main`, `2c5604c01fc5ba5e1a08ec0b98657363974f7bce`.
Ветка патча: `codex/home-v26-reference-cleanup-20260907`.

## Что изменено

- Единая главная для светлой и тёмной темы: боковая навигация, поиск, приветствие, лента, популярные темы, люди недели и новости.
- Растение заменено векторными окнами диалога. Иллюстрация использует цвета текущей темы, внешние изображения не загружаются.
- Отдельная колонка оценок тем убрана согласно последнему согласованию. Реакции на странице самой публикации сохранены.
- Обычная прокрутка страницы. Боковая навигация на широком экране прокручивается отдельно; на телефоне открывается кнопкой.
- Сохранение темы использует реальный ответ API `bookmarked`. При отказе состояние не меняется.
- Экспорт в Telegram сохраняет выбор доступного канала; добавлены удержание фокуса, возврат фокуса и защита от повторного нажатия после успешной отправки в открытом окне.
- «Новые» сортируются по дате; «Популярные» — по числу ответов в полученной выборке; «Тренд» использует существующую выдачу активности за последние 24 часа. «Без ответов» и фильтр сообщества применяются к загруженной выборке API (до 50 записей).
- Сессия передаётся при серверной загрузке, чтобы начальное состояние сохранений соответствовало пользователю.
- Главная делает четыре исходных запроса вместо восьми. Неиспользуемые запросы медиа/услуг/опросов убраны; соответствующие страницы и API сохранены.
- Тестовые пользователи живут только в браузерном тесте. Сбой API не подменяется вымышленными данными.

## Как применить

1. Загрузите полученный `forrum-v26-reference-cleanup-20260907.yml` в `.github/workflows/` репозитория **forrum2**, ветка **main**.
2. В Actions откройте **FORRUM V26 — references and cleanup** и нажмите **Run workflow**.
3. Workflow сверит исходные файлы, создаст отдельную ветку, применит изменения, выполнит сборку и браузерные проверки. Только после успешных проверок отправит ветку.
4. В Summary появится ссылка сравнения с main. Откройте PR и проверьте его перед слиянием. Автоматического слияния нет.
5. После слияния действующие deploy workflow запускаются по своим правилам.

Если исходники уже изменились, патч остановится со списком несовпавших путей до записи файлов. Если целевая ветка существует, повторный запуск остановится, не переписывая её. Для проверки выдачи workflow прикладывает снимки экрана как Actions artifact.
