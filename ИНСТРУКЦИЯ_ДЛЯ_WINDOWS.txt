FORRUM v0.20.2-rc4
ПОЛНАЯ ИНСТРУКЦИЯ ДЛЯ WINDOWS — БЕЗ ОПЫТА ПРОГРАММИРОВАНИЯ

Вам не нужно устанавливать Node.js, PostgreSQL, Prisma или редактор кода.
Всё запускается внутри Docker Desktop.

ВАЖНО ДЛЯ ЭТОЙ ВЕРСИИ
----------------------------------------------------------------------
Запускные BAT-файлы специально сохранены только в безопасной ASCII-кодировке
и с Windows-переносами строк. Поэтому сообщения в чёрном окне будут на
английском. Это сделано намеренно, чтобы обычный Windows CMD не пытался
выполнять части русского текста как команды.

Не смешивайте файлы v0.20.2 с распакованной папкой v0.20.1.
Распакуйте новую версию в чистую папку.


======================================================================
ЧТО ПОНАДОБИТСЯ
======================================================================

1. Windows 10/11 64-bit с поддержкой WSL 2.
2. Не менее 8 ГБ оперативной памяти; желательно 16 ГБ.
3. Не менее 12 ГБ свободного места на диске C:.
4. Интернет при первой установке.
5. Включённая виртуализация процессора в BIOS/UEFI.
6. Архив FORRUM, полностью распакованный в отдельную папку.

Рекомендуемая папка:

C:\FORRUM

Не запускайте BAT-файлы прямо внутри ZIP-архива, из облачной папки или с флешки.
Не используйте в пути русские буквы, очень длинные названия и символы вроде #, &, !.

======================================================================
ШАГ 1. УСТАНОВИТЕ ИЛИ ОБНОВИТЕ WSL 2
======================================================================

1. Нажмите кнопку «Пуск».
2. Напишите: PowerShell
3. Нажмите правой кнопкой по Windows PowerShell.
4. Выберите «Запуск от имени администратора».
5. Вставьте команду:

wsl --install

6. После завершения перезагрузите компьютер.
7. Снова откройте PowerShell от имени администратора и выполните:

wsl --update

8. Для проверки выполните:

wsl --status

Если Windows пишет, что виртуализация отключена, её нужно включить в BIOS/UEFI. Название настройки обычно: Intel Virtualization Technology, Intel VT-x, AMD-V или SVM Mode.

======================================================================
ШАГ 2. УСТАНОВИТЕ DOCKER DESKTOP
======================================================================

1. Скачайте Docker Desktop только с официального сайта Docker.
2. Запустите установщик.
3. Оставьте выбранным вариант WSL 2.
4. Завершите установку и при необходимости перезагрузите ПК.
5. Запустите Docker Desktop через меню «Пуск».
6. Примите лицензионное соглашение.
7. Дождитесь статуса Engine running.

Входить в аккаунт Docker для локального теста обычно не требуется.

======================================================================
ШАГ 3. РАСПАКУЙТЕ FORRUM
======================================================================

1. Нажмите правой кнопкой по ZIP-файлу.
2. Выберите «Извлечь всё».
3. Укажите папку:

C:\FORRUM

4. Откройте C:\FORRUM.
5. Проверьте, что в этой папке видны файлы:

PRECHECK_PC.bat
INSTALL_AND_START_FORRUM.bat
TEST_FORRUM.bat
CHECK_FORRUM.bat
docker-compose.yml

Если внутри C:\FORRUM находится ещё одна папка с этими файлами, откройте именно её.

======================================================================
ШАГ 4. ПРОВЕРЬТЕ ГОТОВНОСТЬ КОМПЬЮТЕРА
======================================================================

Дважды нажмите:

PRECHECK_PC.bat

Он проверит:
- свободное место;
- WSL;
- Docker Desktop;
- Docker Compose;
- корректность docker-compose.yml и .env.

Правильный результат:

SUCCESS: This PC is ready to install FORRUM.

Если окно сообщает об ошибке, исправьте указанный пункт и повторите проверку.

======================================================================
ШАГ 5. ПЕРВЫЙ ЗАПУСК
======================================================================

1. Убедитесь, что Docker Desktop открыт и показывает Engine running.
2. Дважды нажмите:

INSTALL_AND_START_FORRUM.bat

3. Windows может показать предупреждение SmartScreen. Нажмите «Подробнее», затем «Выполнить в любом случае», только если архив получен непосредственно из этого чата и контрольная сумма совпадает.
4. Не закрывайте чёрное окно.
5. При первом запуске Docker скачивает образы и npm-пакеты. Время зависит от интернета и мощности ПК.
6. Скрипт дождётся готовности API и самого сайта.
7. После успешного запуска автоматически откроются:

FORRUM: http://localhost:3000
Тестовая почта: http://localhost:8025

API для диагностики: http://localhost:4000/v1/health
API-документация локальной версии: http://localhost:4000/docs

Важно: localhost означает только ваш компьютер. Другие люди в интернете этот форум не видят.

======================================================================
ШАГ 7. ПОЛНАЯ АВТОМАТИЧЕСКАЯ ПРОВЕРКА
======================================================================

После успешного первого запуска дважды нажмите:

TEST_FORRUM.bat

Проверка состоит из 13 больших этапов:
1. Контейнеры.
2. API и версия.
3. Prisma-схема.
4. Статический анализ кода и импортов.
5. Проверка честности интерфейсных данных.
6. Базовая проверка доступности интерфейса.
7. Автоматические резервные копии.
8. Полный пользовательский и административный сценарий.
9. Генерация Prisma Client.
10. TypeScript typecheck всех приложений.
11. Unit-тесты.
12. Дополнительная резервная копия.
13. Production-сборка API и сайта.

Правильный итог:

ALL AUTOMATIC CHECKS PASSED

Не пугайтесь большого количества технического текста. Важна последняя строка.

======================================================================
ЕСЛИ ПОЯВИЛАСЬ ОШИБКА
======================================================================

1. Не удаляйте папку FORRUM.
2. Не нажимайте RESET_FORRUM_DATA.bat.
3. Дважды нажмите:

CHECK_FORRUM.bat

4. В папке появится файл:

FORRUM_DIAGNOSTICS.txt

5. Сохраните:
- FORRUM_DIAGNOSTICS.txt;
- скриншот окна с первой ошибкой;
- название шага TEST_FORRUM.bat, на котором произошла ошибка.

6. Передайте эти файлы в чат для исправления.

Полезные простые действия перед повтором:
- перезапустить Docker Desktop;
- перезагрузить ПК;
- временно отключить VPN;
- проверить свободное место;
- убедиться, что порты 3000, 4000, 5432 и 8025 не заняты другими программами.

======================================================================
ШАГ 9. ПРОВЕРКА ПОЧТЫ
======================================================================

Mailpit перехватывает письма только внутри вашего ПК и не отправляет их в интернет.

1. Зарегистрируйте новый аккаунт.
2. Откройте http://localhost:8025.
3. Откройте письмо FORRUM.
4. Нажмите ссылку подтверждения.
5. Проверьте восстановление пароля через «Забыли пароль?».

======================================================================
ШАГ 10. LIGHTHOUSE В CHROME
======================================================================

Эта проверка выполняется только после запуска сайта.

1. Откройте http://localhost:3000 в Chrome.
2. Нажмите F12.
3. Откройте вкладку Lighthouse. Если её не видно, нажмите >>.
4. Выберите режим Navigation.
5. Отметьте Performance, Accessibility, Best Practices и SEO.
6. Сначала выберите Desktop и нажмите Analyze page load.
7. Сохраните скриншот результата.
8. Повторите в режиме Mobile.
9. Повторите для главной, страницы сообщества, публикации, профиля и редактора.

Оценка Lighthouse не заменяет ручную проверку клавиатурой и глазами.

======================================================================
ШАГ 11. ПРОВЕРКА КЛАВИАТУРОЙ
======================================================================

1. Перезагрузите страницу.
2. Не используйте мышь.
3. Нажимайте Tab и Shift+Tab.
4. Фокус должен быть заметен.
5. Первой доступной ссылкой должна быть «Перейти к содержимому».
6. Enter и пробел должны активировать ожидаемую кнопку.
7. Фокус не должен прятаться за нижней мобильной навигацией или шапкой.
8. Не должно быть места, из которого невозможно выйти клавишей Tab или Escape.

======================================================================
ШАГ 12. РЕЗЕРВНЫЕ КОПИИ
======================================================================

Автоматически:
- каждые 12 часов;
- база + изображения;
- хранится 28 комплектов;
- первая копия создаётся после запуска.

Папка:
backups\automatic

Ручная копия:
BACKUP_FORRUM.bat

Изменить расписание:
CONFIGURE_AUTO_BACKUP.bat

Восстановить:
RESTORE_FORRUM.bat

Перед первым реальным восстановлением убедитесь, что автоматические тесты уже прошли, и создайте отдельную ручную копию.

======================================================================
ШАГ 13. ОСТАНОВКА И ПОВТОРНЫЙ ЗАПУСК
======================================================================

Остановить, сохранив данные:
STOP_FORRUM.bat

Запустить снова:
START_FORRUM.bat

Не используйте «docker compose down -v» вручную: параметр -v удаляет локальную базу и изображения.

======================================================================
ШАГ 14. ПОЛНЫЙ СБРОС
======================================================================

RESET_FORRUM_DATA.bat удаляет все локальные аккаунты, темы, сообщения и изображения.
Используйте его только для начала тестирования с нуля.

Перед сбросом:
1. Запустите BACKUP_FORRUM.bat.
2. Убедитесь, что файлы появились в backups\manual.
3. Только затем запускайте RESET_FORRUM_DATA.bat.

======================================================================
TELEGRAM — НЕОБЯЗАТЕЛЬНО
======================================================================

Основной тест проходит без Telegram.
Для реальной проверки нужно создать отдельного тестового бота через BotFather и заполнить .env:

TELEGRAM_BOT_TOKEN=токен
TELEGRAM_BOT_USERNAME=имя_без_собаки
TELEGRAM_POLLING_ENABLED=true

После изменения .env:
1. STOP_FORRUM.bat
2. INSTALL_AND_START_FORRUM.bat

Никому не отправляйте токен бота и не публикуйте файл .env.

======================================================================
ЧТО ОЗНАЧАЕТ ТЕКУЩИЙ СТАТУС
======================================================================

Сборка подготовлена для первого чистого локального запуска и полного тестирования.
Она не является готовым публичным сервером.

До публикации в интернете обязательны:
- домен и HTTPS;
- проверенные миграции базы;
- реальные почтовые настройки;
- внешние зашифрованные backup;
- S3/CDN для изображений;
- мониторинг и оповещения;
- нагрузочные тесты;
- независимый аудит безопасности;
- юридические документы;
- исправление всех ошибок, найденных на локальном запуске.

FORRUM Games, реальные платежи, вывод средств и автоматические выплаты остаются последними этапами. AI в проекте отсутствует.
